# knn_search_pthreads

## ΕΙΣΑΓΩΓΗ

Σε αυτή την συνοπτική αναφορά θα γίνει μια περιληπτική περιγραφή της υλοποίησης της εργασίας 0 και ένας σύντομος σχολιασμός των αποτελεσμάτων.

## ΕΡΓΑΣΙΑ 0

Η άσκηση αυτή ζητά την υλοποίηση ενός προγράμματος το οποίο θα χειρίζεται δύο πίνακες, έστω C και Q. Συγκεκριμένα, το πρόγραμμα θα υπολογίζει τις k κοντινότερες αποστάσεις των σημείων του πίνακα C από τα σημεία του πίνακα Q (ή αντίστροφα) και θα τα αποθηκεύει σε έναν νέο πίνακα, ο οποίος θα κρατά τα αποτελέσματα αυτής της διαδικασίας. Στην συγκεκριμένη υλοποίηση υποθέτουμε ότι C = Q.

Η υλοποίηση αυτής της εργασίας μπορεί να γίνει με διάφορους τρόπους. Κύριο εμπόδιο σε όλη την διάρκειά της ήταν ο υπερβολικά μεγάλος χώρος μνήμης που απαιτούσε το πρόγραμμα για μεγάλες διαστάσεις των πινάκων C & Q. Οι μεγάλες διαστάσεις των πινάκων αυτών (~ 20000+ σημεία ο κάθε ένας) οδηγούσαν των τελικό πίνακα αποστάσεων, ο οποίος στο συγκεκριμένο πρόγραμμα έχει διάσταση Ν x Ν (όπου Ν διαστάσεις των C & Q), να απαιτεί περίπου στα `1,6 GB` μνήμης, κάτι που σε συνδυασμό με την απαιτούμενη μνήμη του υπόλοιπου προγράμματος κάνει το πρόγραμμα πολύ αργό ή και αδύνατο να τρέξει σε μια σειριακή υλοποίηση η οποία κάνει χρήση ενός μόνο νήματος. 

Το πρόβλημα αυτό βελτιστοποιήθηκε ως έναν βαθμό με σπάσιμο των πινάκων σε επιμέρους, μικρότερα μπλοκ, στα οποία ο υπολογισμός των αποστάσεων έγινε παράλληλα με την χρήση νημάτων, έτσι ώστε να μειώσουμε την μνήμη που χρησιμοποιεί κάθε στιγμή το πρόγραμμά μας, αλλά και να έχουμε κέρδος σε υπολογιστική ταχύτητα έναντι του απλού αρχικού σειριακού προγράμματος.

## Workflow

- Υπολογίζουμε τις αποστάσεις όλων των σημείων του πίνακα C από τα σημεία του Q, κάνοντας χρήση του μέγιστου αριθμού νημάτων που μπορεί να χειριστεί με εξασφαλισμένη απόδοση το συγκεκριμένο υπολογιστικό σύστημα (4). 

- Τα νήματα εκτελούν την συνάρτηση ``void *knn_distance(void *args_param)``. Η συνάρτηση κάνει χρήση ενός μικρότερου μπλοκ σημείων του πίνακα C (ή Q) και υπολογίζει τις αντίστοιχες αποστάσεις των συγκεκριμένων σημείων από όλα τα σημεία του άλλου πίνακα. Επίσης στην σειρακή υλοποίηση ο πίνακας CQ^T ο οποίος χρειάζεται για τον υπολογισμό των αποστάσεων είναι και αυτός μεγέθους Ν x Ν ενώ στην συγκεκριμένη παραλληλοποιημένη υλοποίηση βελτιστοποιείται ο υπολογισμός και αυτού του πίνακα ο οποίος τώρα έχει σε κάθε νήμα μέγεθος:
``(args_m[i]->N_finish -  args_m[i]->N_start) * N < N * N``. Το μέγεθος αυτό είναι καθοριζόμενο από εμάς και μπορούμε να το προσαρμόσουμε ανάλογα με την μνήμη του υπολογιστή μας.
Επομένως η εφαρμογή των νημάτων σε αυτό το πρόγραμμα, το καθιστά εφικτό για μεγάλους προς υπολογισμό πίνακες και επίσης το κάνει και ταχύτερο, όπως θα δούμε παρακάτω.

- Στην συνέχεια οι υπολογισμένες αποστάσεις αποθηκεύονται στον πίνακα distance και τροφοδοτούνται στην συνάρτηση quickselect η οποία βρίσκει τα k κοντινότερα σημεία από όλες τις αποστάσεις του κάθε σημείου.

Η προσπέλαση των στοιχείων όλων των πινάκων γίνεται με την χρήση της μεθόδου row-major indexing επειδή είναι πιο αποδοτική σε μεγάλα προγράμματα και επίσης είναι cache-friendly. Επίσης επιλέχθηκε και στην υλοποίηση της συνάρτησης cblas_sgem, όπως φαίνεται στο κομμάτι κώδικα που ακολουθεί:

```
    cblas_sgemm(
        CblasRowMajor,     
        CblasNoTrans,      
        CblasTrans,        
        (args->N_finish - args->N_start),                 
        N,                 
        d,                 
        1.0f,              
        args->C_param, d,              
        C, d,              
        0.0f,              
        args->G_param, N               
    );
```

## Results

Παρακάτω ακολουθούν κάποια αποτελέσματα που δείχνουν την βελτιστοποίηση σε ταχύτητα της υλοποίησης με νήματα έναντι της σειριακής υλοποίησης με ένα νήμα:

- Για 8000 σημεία:

``4 νήματα``

**Parallel Time running: 1.116537 seconds**

**Parallel CPU usage time: 4.000000 seconds** 

``1 νήμα``

**Time running: 1.765596 seconds**

**CPU usage time: 1.000000 seconds**

- Για 20000 σημεία:

``4 νήματα``

**Parallel Time running: 12.976000 seconds**

**Parallel CPU usage time: 42.000000 seconds**

``1 νήμα``

**Για 20000 σημεία και υλοποίηση με ένα νήμα και χωρίς διαχωρισμό του προς υπολογισμό πίνακα σε επιμέρους μπλοκ, το πρόγραμμα δεν χωράει στην μνήμη και οδηγείται σε crash.**

Μια αλλαγή που θα οδηγούσε σε περεταίρω βελτίωση το πρόγραμμα είναι ο πίνακας ``distance`` να είχε μέγεθος όχι **Ν x Ν** αλλά **Ν x k**, δηλαδή να αποθηκεύονται σε αυτόν μόνο τα **k** πιο κοντινά σημεία για το κάθε σημείο του πίνακα και όχι όλα.
